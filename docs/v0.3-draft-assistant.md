# v0.3 草案助手实现与验收

草案助手是**各项目通用的能力**。不预设课程、学科或行业，不内置CIE专用任务网络。它根据每份计划的目标、现状、约束和资料，选择适当的需求分析、工作分解与排期方式。下文的公开syllabus仅为早期资料读取验收样本，不是产品定位，也没有写入用户真实项目。

## 用户流程

计划详情 → 草案助手 → 直接输入调整指令（可包含公开 HTTPS 链接） → 自动读取资料、生成修改并更新草案 → 必要时撤销。只有一个消息输入框，支持附加文件、停止和撤销。旧资料表单、设置表单、分析表和提案操作面板已移除，不保留双模式。已确认计划仍须撤回草案才能应用，执行记录不由聊天直接修改。

链接下载最多尝试两次，总上限150秒；只保存完整读取成功的文档，取消后不再重试。聊天中的链接先导入，再提交原指令；导入失败保留输入，不用未读取资料生成结果。

讨论不改执行项。用户明确请求暂定草案时，基础未知用诊断步骤与假设表达，不要求所有细节先填写完整。输出必须是可应用的结构，不能只在聊天文字里声称“已生成草案”。

## 存储与接口

`State.assistants[planId]` 保存原消息、结构化历史摘要、压缩位置、明确约束、锁定环节、每周容量、资料原文/页段、分析表、待应用提案及撤销快照。沿用SQLite账号状态持久化和版本冲突校验；没有新增第三方存储。

所有接口均为同源、登录后POST，携带 `version` 和 `planId`：

- `/api/assistant/chat`：`message` 或 `retry:true`，可带 `partIds`。先保存用户输入，再请求模型；失败以会话错误返回最新状态。
- `/api/assistant/source`：`source:{name,url?,original?,parts:[{location,text}]}`。original为PDF的base64，资料/段ID由后端生成。
- `/api/assistant/fetch`：`url`。只读取公网HTTPS，校验重定向、解析后的地址和实际连接地址；最多5MB，90秒超时，支持HTTP/2协商。返回公开PDF或文本，由浏览器解析后保存。慢站点仍可能超时，可上传本地文件。
- `/api/assistant/settings`：`constraints,weeklyHours,locked`。用户明确保存的约束不由摘要改写。
- `/api/assistant/apply`：`proposalId`。校验当前草案、提案来源版本、图结构、小时估算、锁定节点、资料引用后写入。
- `/api/assistant/dismiss`：放弃待应用提案。
- `/api/assistant/undo`：只恢复仍与上次应用相容的快照，保留对话与来源。

自动压缩只处理历史消息；原文不删。摘要出处必须指向已有消息。超过预算或摘要非法时明确失败，保留旧摘要；不会伪装成压缩成功。保留关键事实的第一道保障是独立的当前计划及用户明确约束，摘要本身仍是模型产物。

## 验收证据与范围

- 后端全量测试、静态检查；新增场景覆盖跨账号访问、聊天与应用分离、撤销、执行计划保护、过时提案、模型截断和重试、请求期间人工修改、锁定节点、引用校验、压缩失败恢复、连续压缩和资料回收恢复。
- 前端覆盖小时精度、每周容量、依赖、等待与独立工作重叠、未知容量不生成日期，另保留原有待办和输入兼容测试。
- 隔离浏览器实际完成聊天生成提案、应用、撤销、刷新后重新打开查看原对话；发现并修复旧全局侧栏样式影响新助手的问题。
- 官方 Cambridge 9702 2025—2027 syllabus 的文字版 PDF，68页，浏览器成功提取为145个带页码的文本段。公网链接曾遇到下载超时；本地上传路径成功。下载超时单独提示，并提供上传替代。
- 真实 MiMo 初轮暴露“只输出文字草案、不返回plan”的问题，已修正提示协议。修正后针对官方PDF第16页的1.1、1.2、1.3三个小节，3/3小节生成带来源引用和任务映射的分析，得到3个可应用节点；该次约40.9秒，输入约7,321 UTF-8字节。仅证明这一页的三个指定小节，不代表整份syllabus覆盖或估时准确性已获人工认证。
- 后续真实验收同样覆盖3/3指定小节，生成8个节点，用时约71.8秒；随后真实摘要连续整理3次，全部16条原消息保留，独立约束与锁定环节未变，最终摘要1,119字节。模型生成的节点数会随拆解粒度变化。
- 前端18项测试通过；后端全量测试及 `go vet` 通过。压缩和工具读取可能增加总耗时，因此草案聊天总时限为180秒、单次模型调用仍为90秒，服务响应时限195秒；超时保留已保存消息和已完成的摘要进度。

## 明确边界

没有自由全网搜索、OCR、跨计划容量优化或自动派发任务。资料分批读取，系统不把“145个文本段”混同于145个学科小节。保留原始聊天与PDF增加本机存储，模型请求不会每次发送全部原文。会话压缩不能保证任意长度对话零语义损失；用户明确保存的约束保持独立且可查，重要历史决定仍可回看原文。
