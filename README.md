# ATriage v0.3.0

个人规则驱动的行动列表。React / TypeScript + Go + SQLite，独立应用，当前不接入 FAI。

## v0.3 草案助手

这是各项目通用的助手，适用于产品开发、活动筹备、经营改进、学习成长等目标。根据当前项目选择分析和拆解方法，不预设为课程规划工具，不内置任何CIE专用流程。

进入 **目标计划 → 计划详情 → 草案助手**。宽屏并排显示计划与聊天，窄屏在详情顶部显示可收起的助手。对话和资料按账号、计划保存，刷新后重新打开同一计划可以继续。

- 用自然语言讨论、增删、拆分、合并环节。AI 返回完整修改提案，逐项展示前后内容和工作量；点击 **应用到草案** 才写入。已执行计划仍须先撤回草案。助手应用保留历史并支持撤销；过时提案和覆盖后续修改的撤销会被拦截。
- **已确认约束与锁定环节** 单独保存用户事实、每周容量及锁定节点；历史摘要不能改写这些字段。可手动保存，也可在聊天中明确提出容量或约束变更，由提案展示前后内容，与计划一起应用和撤销。未保存的手动环节修改先保存再使用助手。
- 资料支持粘贴正文、上传文字版 PDF、读取公开 HTTPS HTML/纯文本/PDF。PDF 在浏览器提取文字，按页分段，原文件保存在本机账号数据中。每份计划最多12份资料，每份最多5MB PDF、600KB提取文字、500段；扫描件 OCR 暂不支持。链接读取不携带账号凭据，拒绝本机、内网和非标准端口。
- 默认读取开头片段，用户可勾选本轮资料段；助手也可按目录自主读取最多2批其他片段。本轮读取位置可检查，引用对应已保存的原文。资料分析表独立于最多30个执行环节，可累计至500条；条目数量不是全文覆盖率。
- 小时工作量保留下界、上界、依据及出处。设置每周容量后计算个人净投入；全为本人执行且小时估算齐全时，进一步按依赖、串行投入、可重叠等待推算相对周数。其他角色容量未知时不虚构整个计划的完成日期。原有整数天计划继续兼容；重排保留已有小时估算，小时调整使用助手提案或手动小时字段。
- **自动 compact**：近期未整理对话达到约7KB时，按最多9KB历史批次整理为结构化摘要，保留近期至少4条原文。摘要包含决定、被否定方案、假设、未解决问题及原消息ID；摘要最大5KB，原聊天不删除。计划、明确约束、原始资料独立保存；每次请求仅装配受限的历史、资料片段和分析片段。
- 每次模型输入采用保守的 **48,000 UTF-8 字节预算**（不是精确 token 数），单次模型输出最多10,000 tokens；超过预算时停止并明确提示，不无限发送全文。压缩失败不覆盖旧摘要；模型失败或截断保留用户消息，可以重试。聊天与压缩共享180秒总时限和原有账号频率限制。
- 删除目标时，会话、资料、分析与计划一起进入回收站；永久清理前也纳入原有固定目录恢复备份。

开发验证：`go test ./... -count=1 -timeout=120s`、`go vet ./...`、`npm test`、`npm run build`。默认测试使用临时数据库和模拟模型；`ATRIAGE_ASSISTANT_BROWSER=1` 启用隔离浏览器验收页面。`ATRIAGE_LIVE_DRAFT=1` 为显式真实模型验收，仅使用公开syllabus样本和虚构目标，读取本机已保存配置，不改生产计划。真实验收记录与边界见 [v0.3 验收说明](docs/v0.3-draft-assistant.md)。

## v0.2.1 目标计划

左侧 **目标计划 → 创建目标计划**。六个输入方向分别为大目标、现状、时间意向、限制、资源线索、暂定成果，每项都有多选快捷项与一行细节。只有大目标的文字必填，其余可留空。生成后仍可在计划详情中随时点选或补充方向；每次保存会保留调整前的输入记录。已加入待办的计划不会因调整方向而自动改动执行项，须先撤回为草案后再重新编排。未生成的输入保留在当前页面会话，刷新或退出后不会保留；已生成草案保存在账号数据中。

AI 生成任务、交付物、依赖、投入与等待天数、重要性、P0—P3 执行优先级以及三种分工建议：亲自执行、他人执行我把关、委派执行。P 级说明不做此项的损失：P0 是有明确后果和时间窗口的生存线，P1 是战略推进，P2 是增益亮点，P3 可延后；它与是否委派独立。原始输入单独保留，AI 假设与待确认问题明确展示。需要已连接 MiMo；失败不使用伪装成 AI 的通用计划。

程序验证任务编号、完整性和循环依赖，生成可滚动的任务网络与相对日程。草案顶部提供添加环节与 AI 重新编排入口；展开单项可修改名称、产出、工期、角色、理由与依赖，或移除该环节。AI 重新编排只能重建依赖、工期与分工，不能擅自增删或改写用户已编辑的环节。网络红色节点为仅按依赖计算的关键路径。同一角色的投入串行，等待可并行；这不是全局最优排程。第 1 天是相对起点，投入天数为估算，不包含既有待办、跨计划容量、节假日，也不会自动把用户时间意向当作硬截止。

一句话添加的内容会先作为大目标保存，可直接进入拆解，也会参与大项目 AI 重排。目标计划与未拆解大目标均可移入目标回收站并恢复；永久清理前会将完整记录写入项目下固定的 `.recovery-trash` 文件夹。**确认计划并加入待办** 会原子追加本计划任务，保护原有顺序并拦截重复确认。已确认计划顶部可撤回草案，执行项与完成记录会保存到该计划的历史版本中；重新确认时，名称、产出与前置链未变的环节沿用原进度和截止日，改动或新增环节重新开始。未完成前置任务时，后续任务显示等待且不能标为完成；前置项“决定不做”不自动解除依赖。当前版本不向他人发送委派通知。每账号最多 50 份目标计划，每份 1—30 个任务，并遵守原有待办数量上限。

## 启动

需要 Node.js 24 和 Go 1.26。双击 **启动 ATriage.cmd**，首次会安装前端依赖、构建页面与后端，随后打开 http://127.0.0.1:8091 。再次启动会检测已有服务，并按正在运行的版本打开新页面，避免浏览器继续显示旧版缓存。后端在后台运行，日志位于 `backend/server.log` 和 `backend/server-error.log`。

手动开发：在 `backend` 运行 `go run .`；在 `frontend` 运行 `npm ci`、`npm run dev`，访问 http://127.0.0.1:5190 。生产构建后 Go 直接提供页面，无需 Vite。

## MiMo API 配置

登录后，点击左侧 **AI API 配置**，只需粘贴 MiMo API Key 并保存。ATriage 自动识别两种官方 Key：`sk-` 开头的按量付费 Key 使用 `https://api.xiaomimimo.com/v1`；`tp-` 开头的 Token Plan Key 自动识别可用的官方区域节点；模型固定为 `mimo-v2.5-pro`。保存时会发出一次极短的验证请求，只有验证成功才保存。

Token Plan 会先连接中国节点；若套餐实际属于新加坡或欧洲节点，ATriage 会自动尝试其余两个官方节点。MiMo 官方说明：按量付费与 Token Plan 的 Key、Base URL 与模型设置以控制台为准。[MiMo Quick Start](https://mimo.mi.com/docs/en-US/quick-start/summary/first-api-call)

API Key 只从浏览器发给本机 ATriage 服务；服务使用本机自动生成的 AES-GCM 密钥加密后写入 `backend/data/atriage.db`，浏览器不会保存或回显 Key。`backend/data/atriage-secret.key` 必须与数据库一起保留；遗失后只需重新粘贴 API Key。对于公共电脑或多人共用同一 Windows 账号，不建议保存个人 Key。

旧的服务器级 `.env` 配置仍可作为开发者默认设置；正常使用不需要创建 `.env` 或填写模型名、URL。

没有配置或请求失败时，使用明确标注的基础规则排序：重要程度 → 截止时间 → 创建时间。基础规则不会理解个人规则文本，不会假装使用 AI。配置 MiMo 后，用户规则和待办内容会发送到 MiMo 用于生成排序建议。

## 使用

1. 注册邮箱、密码、称呼，设置角色、关注目标、规则文本和时区。角色只用于默认偏好，不赋予其他用户数据权限。
2. 一句话创建任务，可补充截止日期、时间、重要程度、说明。仅日期按任务时区的当天结束计算。
3. 新任务先保存，再获取 AI 建议。新任务可以插入列表，已有任务的相对顺序保持不变。
4. 拖拽左侧手柄，或输入数字排名后按 Enter / 离开输入框。改变顺序不会改变重要程度。
5. “查看 AI 重排建议”只预览；点“应用”才改变列表。旧版本建议无法应用。编辑任务和改变规则不会自动重排。
6. 完成和“不做”分别归档，可恢复到末尾。“考虑他人 / AI 协助”只是记录意向，不会发送或执行。

临近截止表示未来 24 小时，逾期只对未完成任务显示。系统不预测工作量是否来得及，不发邮件或系统推送。

## 数据与边界

- 数据在 `backend/data/atriage.db`，数据库写入磁盘，账号间隔离。备份时先正常停止后端，再复制整个 `backend/data` 文件夹，保留 SQLite 辅助文件。
- 密码使用 bcrypt，服务端会话 cookie 为 HttpOnly / SameSite Strict，有效期七天。首版没有邮件验证及自助找回密码，请保存密码。
- 公网部署需 HTTPS、反向代理、`COOKIE_SECURE=true`，并设置合适的 `ADDR`；默认只监听本机。
- 上限为每账号 200 条待办、2000 条总任务；任务标题 300 字，备注 3000 字，个人规则 4000 字。模型请求有 90 秒超时及每账号每分钟 10 次限制；规划和排序共用频率限制。
- 大目标先进入账户回收站；永久清理前会将完整记录写入项目下固定的 `.recovery-trash` 文件夹。需要整理开发文件时，也先移至该目录。

## API

所有写入使用 JSON，除注册登录外均需同源会话。`GET /api/state` 返回版本、个人设置、任务及活动顺序；每次写入携带 `version`，冲突返回 409，由界面刷新后允许重试。

- `POST /api/register`, `/api/login`, `/api/logout`
- `PUT /api/profile`：`{version, profile}`
- `POST /api/tasks`, `PUT /api/tasks`：`{version, task}`
- `PUT /api/order`：`{version, order}`，必须是当前全部待办 ID 的排列
- `POST /api/suggest`：`{version, taskId?}`，指定新任务时仅尝试插入该任务；不指定时返回重排预览
- `POST /api/plans/generate`：`{version, input}`，六项均为 `{choices:[], detail:""}`；检查模型完整结果后原子保存草案，返回最新 State
- `PUT /api/plans`：`{version, plan}`，编辑草案并重新计算；原始输入与来源不可改写
- `POST /api/plans/accept`：`{version, planId}`，原子加入待办，只接受当前账号尚未确认的草案
- `POST /api/plans/withdraw`：`{version, planId}`，将已确认计划撤回草案并保存执行记录
- `POST /api/plans/replan`：`{version, plan}`，AI 基于用户保留的环节清单重新编排依赖、工期与分工
- `POST /api/plans/delete`, `/api/plans/restore`, `/api/plans/purge`：`{version, planId}`，分别移入目标回收站、恢复、永久清理并写入本机恢复备份
- `GET /api/health`：服务身份与 AI 是否配置，不暴露凭据
